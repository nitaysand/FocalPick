FocalPick Guide

The easiest way: the graphical interface (chapter 4). It is available in Hebrew and English, and it has a built-in guide (the "Guide" button or F1). If you prefer the command line, everything is explained further on. Both routes run the same tools.

1. What it is and why it is useful

This is a toolkit (Python scripts) that helps photographers choose their photos. It is designed for two situations:

SituationToolWhen to use it
A. One photo shoot (RAW files, and optionally JPEG and HEIC too)rate_raw.pyYou came back from a shoot with 100 photos and want to know which of the similar photos is the best, and which ones are the "gems" of the session.
B. A full archive (JPEG files)photo_triage.py followed by ai_rate.pyYou have thousands of old photos and want to pull out candidates for a portfolio.

The tools use an AI model to "look" at the photos. You can choose from many providers (Gemini, OpenAI, Anthropic, Groq, OpenRouter and more, and also a model that runs on your own computer). Some of them have a free tier with limits (chapter 3). Your photo files are not changed or deleted. The only thing the tool can write next to a RAW file is a rating file .xmp, and only if you explicitly ask for it.

The rating is a recommendation, not a final verdict. The model can make mistakes, especially between almost identical photos. The comment it writes on each photo helps you check whether the reasoning is right, and the final choice is yours.

2. What you need before you start (one time)

  1. Windows with Python installed (Python 3.9 or later). (If you use the EXE, you don't need Python. See chapter 8.)
  2. Installing the libraries: open a command window (Windows key, type cmd, Enter) and run: 
    pip install pillow numpy
    or, if you have requirements.txt: pip install -r requirements.txt. (Optional: pip install rawpy. If Windows blocks it, see "Troubleshooting". The tool also works without it. To read HEIC files from your phone: pip install pillow-heif.)
  3. A folder for the tool files: save all the tool files in one folder, for example C:\photo_triage: the Python files (photo_tools_gui.py, rate_raw.py, photo_triage.py, ai_rate.py, dupes.py, agreement.py and more), the file providers.json and the lang folder (language files). They must all stay together. The easiest thing is to copy the whole folder as it is.
  4. An API key from the AI provider you chose (chapter 3). The easiest way to start is with Gemini: sign in to aistudio.google.com with a Google account, choose "Get API key" and copy it. No credit card is needed. (A local model such as Ollama does not need a key.)
The key is a password. Don't send it to anyone, and don't take a screenshot of a screen where it is visible. If you have exposed it, delete it on the same site and create a new one.

4. The graphical interface

  1. Starting it: python photo_tools_gui.py from a command window (or double-click start_gui.bat. If Windows blocks it, run it from the command line).
  2. Connecting to AI (at the top): choose a provider, paste a key, click "Show available models" and choose a model that understands images. For each provider, the interface remembers the key, model and address separately. The "Server address" field appears only for providers where you run your own server (Other, Ollama, LM Studio), and the checkbox "Show only free models in the model list" appears only for OpenRouter.
  3. Tabs: "Photo session", "Archive culling and rating", and "Duplicates" (the duplicates tab doesn't use AI, so the provider connection part is hidden on it). On the archive tab you choose between three steps (culling, rating the contact sheets, close check) and see only the fields of the step you selected. The results folder of step 1 fills in automatically for the next steps. You fill in the fields, and on the selected tab click Run.
  4. Advanced: the "Advanced..." button at the bottom opens a window with settings most people never need to touch: grouping sensitivity, the gap in seconds between groups, the search for similar photos far apart in time, maximum photos per group, how many photos compete for the highlights and how many of them get stars, the pre-filter blur threshold, a separate model for the highlights step, and the pause between requests. An empty field in the first three numbers = automatic: the tool knows each provider's limit and learns a model's limit from the error it returns, and the number of highlights is set as a small percentage of the session. The taste check (chapter 7b) is in this window too.
  5. Type of shoot: on the Photo session tab you can choose the "type of shoot" (street, events and people, sports and action, landscape and nature, portrait, cars). The choice adds guidance suited to that type for the AI, for example on the street the moment matters more than sharpness, and in sports the peak of the action. It works together with the taste file and does not replace it. "None" = general rating. Changing the type rates the session again.
  6. Copy model list: the button next to "Show available models" copies the provider's model list to the clipboard, with whatever the provider reports about them, together with a ready question for a chatbot: which of them accept images, which are free and what the quotas are. The list itself does not say what is free, except for OpenRouter, so it is worth verifying against the provider's documentation.
  7. About: in the top row, the version, the license (MIT) and links to the project and to supporting it.
  8. Language and guide: at the top of the window, choose a language (Hebrew or English). Changing it asks you to restart the program. The "Guide" button (or F1) opens this guide in your browser. You can add another language in the file lang/<code>.json (see the README).
  9. Non-RAW files: by default, the photo session works on RAW files only. With the checkbox "Include non-RAW files too" it also works on JPEG, PNG, TIFF and HEIC. If you shot both RAW and JPEG, a JPEG that has a RAW with the same name is skipped, so the same photo isn't rated twice. Stars are written to Lightroom only for RAW files, because Lightroom doesn't read a sidecar file for a JPEG.
  10. The first time on the session tab, "Only check how the photos group, without AI and without an API key" is checked. This is intentional: you see first that the grouping makes sense. To actually rate, uncheck it.
  11. At the bottom: the "Run" and "Stop" buttons (stopping takes up to a few seconds, and progress is saved), "Open results folder" and "Open report". The log shows what is happening, including errors and an explanation of what to do.
  12. Convenience: keyboard shortcuts (copy, paste, cut, select all, undo, redo) also work when the keyboard is set to Hebrew, and there is a right-click menu. When the window is small you can scroll (mouse wheel or scroll bar).
  13. Explanations on hover: when you hover the mouse over a field, a short explanation of what it does appears. A field whose value differs from the default is shown in a different color and in bold, and the "Restore defaults" button puts them back (paths and the provider connection don't change).
  14. Progress and estimate: while running, a progress bar with an estimate of the time left is shown. Before a big job, an estimate of the number of requests and the time is shown, and you can cancel before it starts. The tool also remembers how many requests it sent in the last 24 hours and at what number the daily quota ran out last time, and warns you in advance when the job may stop halfway. This is only an estimate, because the tool can't see usage outside it. For a paid provider, a note to check the price on the provider's site is also shown.
  15. Log: the buttons "Copy all" and "Save log..." are under the log. A copy of every run is also saved in the file run_log.txt in the results folder, so you have something to send when something goes wrong.
  16. Long runs: the computer doesn't go to sleep while running. At the end, if the window is not in front, a sound plays and the program icon in the taskbar flashes. Enter starts a run, and Esc stops it.
  17. Light or dark theme: in the top-right corner of the window, in the "Theme:" box, you can choose "System" (the default: the interface follows the Windows setting and switches by itself), "Light" or "Dark". The choice is saved.
  18. Profiles: in the top-left corner, "Save profile..." saves the tool and model settings under a name, for example "Wedding" or "Old archive". Choosing a name from the list loads all of them at once. Paths and the key are not saved in a profile. "Delete" removes the selected profile.
  19. Dragging: you can drag a folder from Explorer into the window (on Windows). Dragging onto a path field fills it. Dragging to another place fills the source field of the active tab, and a .lrcat file is automatically passed to the catalog selection.
  20. Showing results in a window: the "Show results in window" button opens a gallery of the rated photos. You can sort by score, name or group, filter by a minimum score, limit the view to the session highlights, click a photo to enlarge it, and move between photos with the arrows. From the enlarged view you can show the original file in its folder or copy its path.
  21. Saving settings: settings are saved in the file .photo_tools_gui.json in the user folder. The key is not saved in this file. If you checked "Remember the key on this computer", it is saved in the Windows Credential Manager, and deleted from there when you uncheck it.

5. How to run each tool from the command line (the basics)

  1. Open a command window and go to the tools folder: 
    cd /d C:\photo_triage
  2. Set the key (in every new window, because it is forgotten when you close the window): 
    set GEMINI_API_KEY=YOUR_KEY
    (For another provider: use the variable name from the table in chapter 3, and add --provider name --model שם_מודל to the command. You can also use --key directly in the command.)
  3. Run the command. A path with spaces or Hebrew characters must be inside quotation marks. Tip: in File Explorer, hold Shift, right-click a folder and choose "Copy as path".
Every tool saves its progress as it goes. If a run stops (quota, network error, you closed the window), run the same command again and it continues from the same point.

6. Mode A: rating a photo session (rate_raw.py)

What the tool does

  1. It reads from each RAW file the preview image that the camera saved inside it (fast, no conversion).
  2. It groups consecutive similar shots into one group.
  3. It asks the AI to rate each group: which one is the best, and how each photo does in composition, camera angle and light.
  4. It compares the best photos from all the groups and marks "gems" (💎) only if they are really outstanding. There may be few, or even none.
  5. It creates a report in the browser and a spreadsheet.

What is judged and what is not

The tool is meant to help before editing, so it judges only what can't be fixed later: composition, camera angle, direction and quality of the light, and the moment (expression, timing). It ignores exposure, white balance, colors and noise. In addition, it marks "flags" for things that can't be fixed in editing: missed focus, motion blur, closed eyes, a cut-off subject.

Running it, step by step

Step 1: checking the grouping, without AI and without a key.

python rate_raw.py "E:\Photos\הסשן שלי" --out "C:\rating\הסשן" --prepare-only

Open the file C:\rating\הסשן\report.html in a browser and check: do landscape photos show up as landscape? Are similar photos in the same group, and different ones separate?

Step 2: a small trial with AI (only 3 groups). If you don't use Gemini, add --provider and --model:

set GEMINI_API_KEY=YOUR_KEY
python rate_raw.py "E:\Photos\הסשן שלי" --out "C:\rating\הסשן" --limit 3

Open the report again and check: did the model pick the same photo you would have picked in the group? Are the comments sensible?

Step 3: the full run (the same command without --limit):

python rate_raw.py "E:\Photos\הסשן שלי" --out "C:\rating\הסשן"
Why --out? Without it, the results are saved inside your photo folder (in a folder named _rating), and they may get mixed up with the archive. It's better to save them in a separate place.

How to read the report (report.html)

  • At the top: "Session highlights", with 💎 for the gems.
  • Below: each group, with its photos sorted from best to worst. The green frame and the label "Best in group" mark the winner.
  • For each photo: the file name, an overall score (1–10), the composition, angle and light scores, red flags (if any), and a short comment in Hebrew.
  • Clicking a photo opens it at full size. To find it in Lightroom: Library Filter → Text → File Name, and paste the file name.
  • The scale: 5 = an ordinary photo that stays, 7 = strong, 8 = excellent, 9–10 = outstanding. The model is deliberately strict, so scores of 3 to 5 are normal.

The same data is also in ratings.csv (opens in Excel). Don't leave it open in Excel while the tool runs, because the tool won't be able to write to it.

7. Mode B: a photo archive for a portfolio

Two steps: basic culling without AI, then AI rating.

Step 1: photo_triage.py (culling without AI)

python photo_triage.py "E:\Photos\Archive" --list-cameras
python photo_triage.py "E:\Photos\Archive" --out "C:\triage"
  • The first command only shows which cameras appear in the files (and if you set --cameras, it marks the approved ones).
  • The tool takes JPEG files only. To limit it to certain cameras, add --cameras "R6 Mark II,250D" (default: all cameras). To skip folders by name, add --exclude word. The tool also rejects blurry or very dark photos.
  • It creates small copies (thumbs), numbered contact sheets (sheets) and a report (report.csv, with the reason for each rejection). Nothing is deleted.
  • You can adjust the sensitivity with --blur 40 (a lower number = more lenient).

Step 2: ai_rate.py (AI rating)

python ai_rate.py rate "C:\triage" --limit 2
python ai_rate.py rate "C:\triage"
python ai_rate.py refine "C:\triage"

Here too you can add --provider, --model, --key, --base-url and --delay. python ai_rate.py models "C:\triage" shows the available models.

  • rate rates the contact sheets (a score of 1–10 and a category for each photo) and saves to ai_scores.csv.
  • refine checks the best photos again at a higher resolution, and copies the originals of the finalists into the finalists folder. Portraits get a stronger check.
Protection from old results: if you run step 1 again on the same folder, the photo numbers change. The tool detects this, moves the old ratings to a folder named old_results_... and starts a new rating, so the results don't get mixed up.
Important limitation: in archive rating, the model sees small images inside a contact sheet, so it makes quite a few mistakes. Don't delete photos based on a low score; use it only as a hint. If the rating doesn't match your taste, try Mode A on small groups.

7a. Duplicates (dupes.py)

Finds files that are exactly identical (the same file copied several times), and the same photo saved again at a different size or compression. The tool only reports, and doesn't move or delete anything. In each group it suggests keeping the largest image.

Burst shots, or several photos from the same angle, are not duplicates. For two files to count as "nearly identical," they must look almost identical at every pixel, and their capture times (EXIF) must also match. Two burst shots were taken at different times, so they won't be matched. Two photos that look identical, where one of them has no capture time, are matched only if there is no conflict in the times.

python dupes.py "D:\Photos" --recursive
python dupes.py "D:\Photos" --out "D:\dupes_report" --no-near

In the interface: the "Duplicates" tab. The report (report.html, with thumbnail images) and the spreadsheet (duplicates.csv) are saved in the report folder.

7b. Matching your taste (agreement.py)

A natural question is how far you can trust the AI's rating. This check (in the "Advanced..." window) compares the results of a rated session with your choices: the stars and Pick flags you gave the same photos in Lightroom. It doesn't send anything anywhere, and it doesn't change the catalog (the catalog is read from a temporary copy).

  1. Rate a session yourself in Lightroom, one that the tool has already rated. Important: if the tool wrote stars to Lightroom and they were imported, those stars belong to the AI itself, and the comparison is meaningless. Use a session that was rated before the tool was used on it.
  2. On the tab, choose the session's results folder (where ratings.csv is), the catalog file, and how many stars count as your choice (default: 3). A photo with a Pick flag always counts as your choice. Photos without stars count as photos you did not choose.
  3. Click Run. The result appears in the text in the log, and in the report (agreement/report.html) with the spreadsheet agreement.csv.
MetricWhat it means
Separation power (AUC)The chance that a photo you chose got a higher score than a photo you did not choose. 0.50 = like flipping a coin, 1.00 = perfect. Roughly 0.80 and above = a good match, 0.65–0.80 = moderate, below that = weak.
Match at the top of the rankingAmong the photos the AI rated highest (as many as the number of photos you chose), how many you actually chose, compared with what would happen by chance.
Match within groupsIn groups of similar shots: how often the photo the AI picked as best is one of the ones you chose.
HighlightsHow many of the highlights the AI picked were also picked by you.
Rejected in the upfront cullingPhotos you chose that the tool skipped in advance. If there are many, lower the blur threshold.

The report also shows the photos you chose that the AI rated low, and the photos the AI rated high that you did not choose, so you can see what it missed and what it raised by mistake. When you chose only a few photos (fewer than 15), the result is not stable, and the tool notes this. If the match is weak, try another model, or describe your taste in the taste file.

The check was built around the structure of the Lightroom Classic catalog, and it was tested only on a mock catalog. If there is an error reading the catalog, it is shown in the log.

7c. Double check with another model

Instead of relying on one model, you can rate the session with two models and let a third model decide only the disagreements. On the "Photo session" tab, tick Double check and choose a provider and an extra model (a different provider is fine, with its own key).

When the extra model (or the judge) belongs to a different provider than the main one, its own API key field and a Show available models button appear below the choice, as in the main connection. A key already entered for that provider, saved or set on the computer, is filled in for you. The "Server address" field appears only for providers where you run your own server. The key is saved only if you ticked "Remember the key".

  1. Both models rate the same photos. When their scores are far apart (default: a difference of 2 points or more), the photo counts as in dispute.
  2. In a group of burst shots, a dispute is when the two models picked a different best shot.
  3. If you chose a judge (in the "Advanced..." window), only the photos and groups in dispute are sent to it. For a single photo the final score is the median of the three scores. For a burst, the photo that two of the three models picked wins. If all three picked a different one, the group is marked "Not settled".
  4. Without a judge the final score is the average, and the disagreements are marked in the report.

Should the judge be shown the earlier scores? By default, no. A judge that sees "one gave 3 and one gave 8" tends to lean toward one of them, and then it is no longer an independent opinion. You can turn this on in the "Advanced..." window.

The photos are sent to every provider you chose, and before each run the tool shows which provider gets what and roughly how many requests. It is usually about double the number of requests, plus a small part for the judge, so on a free daily quota it means fewer photos per day. The report shows each model's score, and a line at its top summarizes how many photos were in dispute.
python rate_raw.py "D:\Photos\session" --model gemini-2.5-flash --second-provider openai --second-model gpt-4o-mini --judge-provider anthropic --judge-model claude-haiku-4-5-20251001

8. EXE version (no Python)

  • Running build_exe.bat builds FocalPick.exe in the dist folder. It attaches the lang folder and THIRD_PARTY_NOTICES.txt to it, if they exist. (Before building, it's best to run python make_notices.py to update the list of library licenses.) You can copy just that file to another Windows computer, and there too you don't need Python.
  • The EXE is not digitally signed, so Windows (especially with Smart App Control) or an antivirus may block it or warn about it, even when it is safe. If this happens, run it with python photo_tools_gui.py.
  • The first start is a little slow. There is no terminal window, so if it doesn't open, run it from the command line to see the error. The rawpy library is not included, and the tool reads RAW files with its own internal method.
  • It was built on Windows, so it works only on Windows. It has not been tested on a computer without Python.
  • Mac: there is no EXE. With Python from python.org (including Tk), run python3 photo_tools_gui.py or double-click start_gui.command. Dragging files into the window works only on Windows, and the key is saved in the settings file rather than in secure storage. The interface has not been tested on Mac.

9. Privacy and quotas

  • Privacy: the photos are sent to the provider you chose. On free tiers, the provider (for example Google, or the providers behind the :free models on OpenRouter) may use the content to improve its products. Only previews or small copies are sent, not the original files, but if they include photos of people, keep that in mind. The previews are re-created and don't carry the EXIF data of the original (GPS location, camera details and more). A local model (Ollama, LM Studio) doesn't send anything out.
  • Quotas: each model has a daily and a per-minute request limit, and the limits are separate for each model. In a session, each group is one request (plus one more for the highlights step), so 30 groups amount to about 31 requests. When the daily quota runs out, the tool stops immediately and explains why, and progress is saved. Run it again the next day, or switch to another model or provider. You can check your Gemini quota at ai.dev/rate-limit. The tool remembers locally how many requests it sent and at what number the quota ran out last time (the file .photo_tools_usage.json in the user folder, with no photos and no keys), and uses this to warn you in advance.

11. Quick summary

Graphical interface: python photo_tools_gui.py. Command line:

cd /d C:\photo_triage
set GEMINI_API_KEY=YOUR_KEY
python rate_raw.py "session_folder" --out "C:\rating\session" --prepare-only
python rate_raw.py "session_folder" --out "C:\rating\session" --limit 3
python rate_raw.py "session_folder" --out "C:\rating\session"

Then: open C:\rating\session\report.html in a browser.

What was tested: extraction from CR3 files, grouping, and rating with Gemini were tested on real files. Groq and OpenRouter were only partly tested. The other providers, the interface, JPEG and HEIC files, the match check, and everything related to Lightroom (writing XMP and reading the catalog) were tested only on mock data or servers, so try them first on a small copy. The interface has not been tested on Mac.
